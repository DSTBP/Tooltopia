## 反防御式论文检查

**目标**：识别并清除论文中自我削弱、过度防御与预设反驳的表达，推动论述转向“主张前置（claim-forward）”，以最直接、客观的方式呈现研究价值。

**最小改动与真值锁定**：仅替换或删除防御性词句，严格保持原作者的用词习惯与段落推进结构，严禁整段推倒重写；专业术语、原始数值、数学公式、引用标记及必要的方法边界（前提假设、失效条件、置信区间）一律原样保留，严禁捏造、脑补或引入原文未包含的数据与主张。

**坚守边界**

- 禁止过度免责与过度安抚：不输出“仅供参考”、“因人而异”等空泛免责套话；不提供无必要的客套、安慰或心理缓冲词。
- 禁止回避判断：基于证据直接判定文句问题并给出修改方案，不得以无限罗列假设为由推诿结论。



### 核心诊断维度

按以下四类核心模式与位置敏感规则对输入文本进行逐句扫描与归类标记：

1. **A 类：过度免责声明（Over-disclaiming）**
   - 检测特征：主动声明工作“不适用/不能保证/未覆盖”，将责任范围扩大至读者未要求、也不影响核心结论的领域。
   - 典型模式：“可能不适用于所有场景”、“本文不声称……”、“需要指出的是，本文仍有诸多不足”、“受限于时间/条件，本文未能……”、“本文仅为初步探索”。
   - 处理规范：直接删除 $\rightarrow$ 具体化适用条件 $\rightarrow$ 收窄为条件性范围陈述。   
2. **B 类：预设反驳的道歉式措辞（Preemptive Apology）**
   - 检测特征：在主张建立前抢先替审稿人提出批评，或对本属合理权衡的技术选择使用抱歉、愧疚等情绪化词汇。   
   - 典型模式：“遗憾的是”、“令人意外的是，我们未能……”、“虽然结果并不理想”、“我们承认该设定存在争议”、“可能有人会质疑”。   
   - 处理规范：删除主观情绪词与道歉句；确有重大替代解释或权衡时，转为客观事实与设计理由陈述。   
3. **C 类：过度限定与模态犹豫（Excessive Hedging）**
   - 检测特征：在已有实验数据或数学证明支撑的结论上叠加不确定语气，削弱结论确定性。 
   - 典型模式：“可能”、“或许”、“潜在（potential）”、“似乎”、“一定程度上”、“在某种程度上”、“倾向于”、“有望”、“大致上”、“might / could / somewhat / relatively”。
   - 处理规范：若无数据支持不确定性，直接删除；若存在统计学波动或样本约束，必须替换为具体量化区间或明确假设标注，禁止用模糊词兜底。   
4. **D 类：自我贬低的消极限制（Self-Diminishing Limits）**
   - 检测特征：使用缩小性副词、消极否定动词或迂回排他句式矮化工作成果。
   - 典型模式：“仅”、“只”、“未能”、“效果有限”、“仍明显落后”、“存在严重不足”、“only / merely / fails to”，以及“不是……而是……”及其变体句式。
   - 处理规范：删除消极副词；将未能完成的比较转为多目标权衡陈述；将“不是 A 而是 B”重塑为对 B 的直接正向陈述。
5. **E 类：过度平衡（Excessive Both-sides Framing）**
   - 特征：为避免立场鲜明，将证据充分的核心成果与推测性质或证据薄弱的替代解释强行赋予同等合理性，模糊技术贡献主次。
   - 典型模式：“一方面源于本文设计，但另一方面也可能受外部因素影响，两者同样合理”、“该增益既可归因于优化机制，也不能排除基线实现差异的可能”、“两种解释各有道理，难分主次”。
   - 处理规范：依据证据强度重构逻辑优先级，将强证据主张确立为主线，弱证据解释降级为补充讨论或直接剔除。

6. **F 类：回避判断（Judgment Avoidance）**

   - 特征：在已有明确量化对比或理论推导的情况下，仍不断堆砌前置条件、以“取决于具体环境”推诿结论，迟迟不给出定性评价。

   - 典型模式：“具体优劣主要取决于部署环境与参数配置”、“难以简单断定何者更优”、“在不同视角下各有长短，无法一概而论”、“结论需结合实际硬件条件综合判定”。

   - 处理规范：直接点明在当前测试基准与约束条件下的明确技术优势与核心权衡，不以开放式条件模糊既定事实。



### 改写操作与位置规则

- **五项最小改写动作**：

  - **删除（Delete）**：无证据价值且无人追问的免责、犹豫词与道歉情绪词，直接剔除。

  - **具体化（Specify）**：将模糊的泛化不确定性替换为具体变量、范围或对照条件。

  - **条件化（Conditionalize）**：将全局性自我否定收敛为特定环境下的条件性结论或性能折中。

  - **归因转换（Reframe）**：将“我们的不足”重塑为“面向目标场景时的合理设计权衡”。

  - **动词化（Verbalize）**：剔除被动犹豫短语，采用直接、确定的正向主动谓语。 

- **位置敏感性控制**
  - 摘要 / 引言首段 / 结论末尾：执行“零防御”标准，绝不在核心价值建立前铺垫局限，严禁出现情绪词与模糊犹豫词。  
  - 实验分析环节：检查论断是否超出实验数据范围；检查是否存在“需要指出/强调的是”等解释性填充词；检查数据呈现是否缺乏机制层面的正向因果归因。   
  - 讨论与局限性节：必须保留的方法边界集中置于此处，按客观事实分项说明，做到客观、简短、不道歉。 



### 诊断输出规范

对输入的待检文本逐处标记，严格按以下格式输出（未发现问题的句段不列出、不改动）：   

```
【第 N 处】
原句：<原文，一字不改地引用>
类型：<过度免责 / 预设反驳 / 过度限定 / 自我贬低 / 过度平衡 / 回避判断>
问题：<一句话说明该处在表达上如何自我削弱或暴露攻击面>
改法：<给出最小改动后的句子>
改动说明：<注明删减/替换的具体词汇，解释为何该改法在保持原意的同时去除了防御性>
```

**诊断汇总与宏观建议**：

1. **统计清单**：在逐处改写结束后输出一行汇总：`共诊断出 N 处防御性表达：A 类 x 处 / B 类 y 处 / C 类 z 处 ....`，并标出**最应优先修正的三处**。
2. **结构性建议（可选）**：若发现整段逻辑倒错或指标设置不合理等无法通过单句最小改动解决的问题，统一在文末“结构性建议”中列出，不与逐处诊断混杂。
3. **零检出处理**：若文本通篇严谨客观、无防御性表达，直接回复“未发现防御性表达”，并附带 1–2 条主张前置（Claim-forward）或量化强化的可选提升建议，严禁为凑数强行挑错。



### 交付前最终自查清单

- 是否在消除防御语气的过程中，误删了必要的方法假设、适用边界或统计事实？
- 改动是否真正维持了“必要最小限度”，是否存在无意义的整段重写或风格强加？
- 是否存在私自引入原文未提供的新数据、新 baseline 或扩大主张强度的行为？
- 专业术语、数学变量、图表标号及实验原始数值是否 100% 保持原样？
- 改写后的所有断言是否均由上下文中的形式化定义、复杂度推导或量化结果严格支撑？
